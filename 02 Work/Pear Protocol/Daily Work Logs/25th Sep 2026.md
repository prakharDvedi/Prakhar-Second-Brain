## PR #923 (composer cross-provider fallback): review, 2 fixes, test, live trial

- **Context:** [#923](https://github.com/pear-protocol/agent-pear-v2/pull/923) (mine, opened 2026-09-23, still open to `development`). A Cerebras tokens-per-minute 429 on the composer surfaced as `Delay was aborted`: the SDK retry backoff outlasted the 30s abort, then the fallback (same model, **same Cerebras key**) hit the same quota. The user got the error reply after 88s (trace `a5b982db36d1029bd46d7e8e71c4db26`). The first commit `df486dce` moved `composerFallback` to `openai/gpt-oss-120b` on OpenRouter and set primary `maxRetries: 0`.
- **Review (`/code-review high`, no verify pass):** 10 candidates. The top one was confirmed by reading `ai@6.0.205`: in `streamText`, an error on a later step (after a tool call) does not throw. It becomes a stream error part, `textStream` ends empty, and `usage` resolves from the earlier step. So a 429 on step 2+ never reached the fallback and failed as "composer prose stream was empty". **Correction to my first framing:** that path was already broken for 429s before #923 (the retry wait was aborted anyway). #923's own regression is narrower: a transient step-2+ 5xx lost its quick retry.
- **Pushed `ae33a54c`** (`--no-verify`, no AI trailer): the stream path falls back on "nothing emitted", not only on a throw. The fallback is built with `resolveNodeModel(LLM.composerFallback)`, so its own `timeoutMs`/`temperature` apply (they were dead config) and a bare name still routes to Cerebras.
- **Pushed `0faadd94`:** `composer/agent.spec.ts`, 4 tests on the real `streamText`/`generateText` with `MockLanguageModelV3`. The step-2 test fails on `df486dce` and passes on the fix.
- **Live trial** (real Cerebras + OpenRouter, 429 injected into a chosen Cerebras call via a `fetch` patch): all 6 cases recovered. Stream step-1 10.0s, stream step-2 17.9s, invoke step-2 29.8s (the thinnest margin), ~90k-token prompt 17.2s. On `df486dce`, the step-2 case failed 2/2 in under a second. One OpenRouter gpt-oss host (AkashML) rejects inputs over 131k tokens.
- **PR description updated** with the results table. **Not covered:** a real Cerebras 429 (the injected one used the same body shape).
- **Left for follow-up (not fixed):** no gpt-oss `maxOutputTokens` cap on the OpenRouter calls; the same retry-wait-vs-abort problem on other Cerebras call sites (e.g. `advanced.extract`); Cerebras not excluded from OpenRouter routing.
