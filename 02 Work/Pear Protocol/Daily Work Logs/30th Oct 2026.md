## Narrative: design review and replay eval prep (later)

Design talk, no code changes to the product. Plan note: [[Elfa Narrative v1 — Plan]] (see its Update section).

**Design points settled in discussion**
- The Haiku judge replaces only Elfa's matching step ("does this post report this watch happening"). Elfa's other jobs move into our own code: collection (twitterapi poller), firing (`SIGNAL_QUEUE`), cooldown (shared Redis keys), evidence (the matched tweet), narrative pair (#1184).
- Harness stays out of collection and judging. Shipped Harness roles: interest distiller (exists, nightly, Cerebras fallback), verify of judged candidates (v1.1, ~20/day, never blocks an alert, needs a Railway → Hetzner bridge). Coverage sweep, watch backtest and allowlist review are later.
- Math and news are additive: one rule store, one per-topic gate, one delivery path, two detectors.

**Code inventory on `epic/elfa-replacement`**
- Have: arming without Elfa (`d4befdc5`), math shadow poller as the template, Pear-sourced fires in `signal.processor`, user caps, Haiku pattern (`rule-builder.agent.ts`), Harness pattern (`runClaudeStructured` + breaker).
- Mostly have: evidence from the tweet. `signal.processor` already fetches the tweet named in `raw.trigger.matchedConditions[].match.url` and skips `fetchEventSummary` when it finds it. The poller only has to write that shape.
