### Decision — mirror the weekly board's params, no separate global/competition board (senior call)

- The FE has TWO leaderboard reads with opposite eligibility: `use-weekly-leaderboard.ts` sends `includeUnlinkedX: false` (linked-X only — the weekly campaign board whose pot X feeds); `use-trading-competition.ts` sends `includeUnlinkedX: true` (everyone, volume-only draw).
- The agent mirrors the WEEKLY board — `currentWeeklyLeaderboard` hard-codes `includeUnlinkedX: false` — so it is linked-X eligible, matching the weekly dashboard. Senior (GPSxtreme) confirmed weekly params are fine and **no separate global/competition board is needed** for AITA week.
- Consequence: the agent does NOT expose the all-accounts competition board. Raw-volume standings that include unlinked accounts are out of scope by decision, not omission — worth noting because "competitions" in casual framing could imply otherwise.

### Correction — default is ROI, not volume (later same day, PR #659)

Second senior (huf, business) clarified: **the competition week is judged on ROI**, so the UI/agent should lead with ROI, not volume. This refines the earlier volume framing (eligibility — weekly, linked-X — is unchanged; only the default *metric* moved).

- Flipped both defaults to ROI (commit `629e48a8`): `currentWeeklyLeaderboard` now defaults `sortBy` to `roi` (the NL composer pre-fetch inherits it), and the `/leaderboard` TG command fetches ROI.
- The TG card had to become **metric-aware** — it was volume-hardcoded, so a bare default flip would have ranked by ROI while printing volume. Header now reads "Ranked by <metric>"; rows show the ranked metric (ROI as a %, "—" for unmeasured ROI; volume/PnL still render as USD when explicitly sorted).
- Backend already supports all sorts (volume / trades / PnL / ROI) — this was a default/priority change, not a capability gap. Volume and PnL remain reachable via an explicit ask (the inline toggle switches venue, not metric).
- Note on ambiguous NL prompts ("show me leaderboard"): the composer (temp 0.5) sometimes answers with the ROI board and sometimes emits a clarify menu with option buttons — LLM discretion + history-sensitive, not a coded rule. Deemed acceptable (a clarify is fine). The `/leaderboard` slash command is deterministic and never asks.
