## Built: `codectx`, persistent codebase retrieval (Graphify + embeddings)

- Set up a persistent code index so agents stop re-grepping the repo each session. There is one global command, `codectx "<question>"`, and a Claude Code command, `/codebase`. Full guide: [[Codebase Retrieval with codectx (Graphify + Embeddings)]].
- Upgraded Graphify to 0.9.69 (`uv tool`) and built an AST graph of agent-pear-v2 with no LLM: 13,484 nodes and 36,110 edges. It lives under `~/.local/share/code-intelligence/pear-protocol-agent-pear-v2/`.
- Embedded 12,393 entities with `openai/text-embedding-3-small` (1024 dims) through OpenRouter. Hybrid search: semantic seeds, then 1–2 graph hops, then rerank, with tests demoted and output capped at about 1,200 tokens. Updates are incremental, driven by a git-state fingerprint.
- Total OpenRouter spend was $0.18, measured from the key usage delta. Most of it went on the `--enrich` attempt below.

## Investigated

- **MSIX AppData virtualization.** The index first landed in the Claude app's private `Packages\Claude_…\LocalCache` copy of `%LOCALAPPDATA%`, where a normal terminal can't see it. I moved it to `~/.local/share`. Lesson: [[Engineering Lessons#A packaged desktop app's writes to AppData can land in a private virtualized copy]].
- **`--enrich` (LLM doc reading) with `qwen/qwen3.8-flash`.** Replies kept getting cut off, so graphify split the batches down to 3–4 docs and was still getting cut off, and every attempt was billed. I stopped it at about $0.15. It is now opt-in only (`codectx --enrich`); `--refresh` never calls an LLM.
- **The first `/codebase` session fell back to keyword mode.** The key was set as a user env var after the Claude app had started, and the fallback message wrongly said "no embedding index". Fix: `codectx` now reads the saved user env var directly, and the fallback reason is shown accurately.

## Measured

- Same prompt ("trace a trade from Telegram → execution → reply"), keyword fallback vs semantic `codectx`: 148s → 94s, 20 → 10 model round-trips, 28 → 10 grep searches, 1.73M → 0.88M context tokens, same answer coverage (9/10 key functions). n=1, and the first run isn't a pure without-codectx baseline. A clean headless A/B test was started.
- Clean headless A/B (`codectx-bench --ab`, Opus 5.5, codectx blocked in the "without" arm): $0.89 vs $1.15 (−22%), 23 vs 31 round-trips, 10 vs 17 grep searches, 2.29M vs 3.08M context tokens, 10/10 vs 9/10 key functions. Wall time was slightly worse with codectx (178s vs 166s). n=1 per arm, so directional only. Details: [[Codebase Retrieval with codectx (Graphify + Embeddings)#Measuring whether it helps]].
