## #1162 Stage 0.2: record provider/model per basket run (investigation only, no code)

- No branch or code yet. Working tree clean on `feat/basket-eval-script`.
- How the provider is chosen (confirmed in code): `apps/context/src/basket-runner.module.ts` picks `ClaudeBasketAgentProvider` when `BASKET_LLM_PROVIDER=claude`, else the OpenRouter `BasketAgentProvider`. Fixed per process, no fallback between them.
- Model: OpenRouter uses `LLM.quant.model` (`openai/gpt-5.3-codex` in `apps/context/src/config/models.ts`). Claude CLI uses `CLAUDE_MODEL ?? "opus"` in `claude-code.client.ts`. The CLI envelope also reports the resolved model per call (`runStructuredWithMeta`), but plumbing that per basket is a bigger diff.
- How earlier `made_baskets` columns shipped (commit `3ee2c7b5`): schema edit plus a hand-applied `ADD COLUMN IF NOT EXISTS` on the shared prod quant DB. No `push:quant` on purpose, because a full push would drop tables owned by pear-stat-arbs. The quant DB is externally owned.
- Finding: a provider/model column on `made_baskets` would leak internals.
  - `apps/agent/src/ai/tools/quant/recent-made-baskets.tool.ts` returns every column except an `omit` list to the agent LLM.
  - The external `/baskets/latest` FE API reads the table with `SELECT *`.
  - The twitter `read-quant-db` tool lets the LLM write raw SQL on quant.
- Options:
  - **A (recommended):** new run table in the context DB (owned here, `push:context`), e.g. `BasketRun { runAt, platform, provider, model }`, written by the cron. Nothing user-facing reads it. The eval script joins on `run_at` + platform.
  - **B:** `llm_provider` / `llm_model` on `made_baskets` plus an `omit` in the agent tool. Still exposed through `/baskets/latest` unless the external API drops them. Needs a manual ALTER on prod quant.
- Asked which option. Answer was "no preference", so not decided yet.
