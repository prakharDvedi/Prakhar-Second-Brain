## Correction: the coverage backtest is not a ship gate

- My #1069 comment called the backtest a pass. The user challenged it, and they were right: it is close to circular. The ranking is built from what traders hold and opened, then scored against what the same traders open next week, so it mostly measures habit persistence. It also skips the chain #1066 changes: it puts the ranked 20 straight into the idea universe, while #1066 only feeds them to daily sentiment (BTC/ETH are already fed via OI and still absent from ideas on 11–14 of 21 days).
- Posted the backtest ([comment](https://github.com/pear-protocol/agent-pear-v2/issues/1069#issuecomment-5925182798)), then the correction ([comment](https://github.com/pear-protocol/agent-pear-v2/issues/1069#issuecomment-5925215680)); fixed the same claim in PR [#1070](https://github.com/pear-protocol/agent-pear-v2/pull/1070)'s description.
- What still holds: `--metric` reproduces the frozen baseline exactly; the generator's output omits assets traders trade; the ranking is a stable input.
- Revised gate: an offline generator replay with vs without the change; the live nightly metric stays the judge of adoption.
- Lesson: a backtest that scores a signal against the behaviour it was built from proves persistence, not impact. Check what the shipped change actually alters before using a proxy as a gate.
